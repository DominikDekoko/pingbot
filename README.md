# Pingbot

Telegram-бот на Python / Telethon / SQLite: личные списки упоминаний и `@all`.
Два контейнера в одной сети: бот → MTProto → Flowseal tg-ws-proxy → Telegram.
Прокси собирается из закреплённого коммита upstream, его порт не публикуется на хост.

## Запуск

1. Создайте бота через [BotFather](https://t.me/BotFather), получите `BOT_TOKEN`.
2. Получите `API_ID` и `API_HASH` в [API development tools](https://my.telegram.org).
   Telethon требует их и при авторизации бота; вход в пользовательский аккаунт в приложении не нужен.
3. Скопируйте настройки и заполните четыре обязательных поля:

   ```sh
   cp .env.example .env
   python3 -c 'import secrets; print(secrets.token_hex(16))'
   ```

   `BOT_TOKEN`, `API_ID`, `API_HASH`, `TG_WS_PROXY_SECRET`.
   Последнее поле — результат генерации, 32 hex-символа без `dd`/`ee`.
   Один секрет автоматически передаётся в оба контейнера.
4. Запустите (нужны Docker Compose v2, доступ к GitHub и реестру образов):

   ```sh
   docker compose up -d --build
   docker compose logs -f bot
   ```

5. Добавьте бота в чат и назначьте администратором. Это позволяет видеть обычные
   сообщения и получать участников, в том числе при скрытом списке.
   Если бот не администратор, отключите Privacy Mode через BotFather (`/setprivacy`),
   затем заново добавьте его в чат; получение участников всё равно может требовать прав администратора.

SQLite, незавершённые диалоги и сессия Telethon сохраняются в volume `bot-data`.
`docker compose down` их сохраняет, `docker compose down -v` удаляет.
Не запускайте несколько экземпляров бота с одной сессией. При замене бота используйте
отдельный volume: приложение проверяет соответствие аккаунта токену.
`.env` и файлы сессии не попадают в Git и образ бота. Логи самого Flowseal могут содержать
секрет прокси — не публикуйте их без удаления секрета.

## Использование

В личке нажмите «Старт» (или отправьте `/start`). Появятся две постоянные кнопки:

- **Мои фразы** → выбор фразы, добавление, изменение и удаление.
- **Мои списки** → выбор списка, добавление, изменение участников, переименование и удаление.

Всё управление выполняется кнопками под сообщениями. Текстом нужно вводить только
значения, когда бот их запрашивает: название списка, фразу или участников через пробел.
Удаление требует нажатия «Да, удалить». «Отмена» возвращает в главное меню без сохранения
вводимых изменений. Переход в другой раздел также отменяет текущий ввод.
Если элементов много, в меню появляются кнопки перехода между страницами.

Пример настройки:

1. «Мои списки» → «Добавить список» → введите `дота 2` → введите `@alice @bobby`.
2. Аналогично создайте список `сотрудники` с другими участниками.
3. «Мои фразы» → «Добавить фразу» → введите `я иду на работу`.
   Фраза `я иду домой` уже добавлена при первой регистрации; её можно изменить или удалить.
4. В чате с ботом используйте любое сочетание:

   ```text
   я иду домой дота 2
   я иду на работу дота 2
   я иду домой сотрудники
   я иду на работу сотрудники
   ```

Каждая личная фраза подходит ко всем личным спискам. Состав упоминаний определяется
названием списка, а не фразой. Сопоставляется всё сообщение целиком без учёта регистра
и лишних пробелов. Если подходят несколько сочетаний, выбирается самое длинное
совпавшее начало-фраза, для которого существует список. Если фраз нет, личные списки
не вызываются до добавления хотя бы одной фразы; `@all` работает независимо.

Фразы и списки всегда принадлежат автору сообщения. Названия и фразы могут совпадать
у разных пользователей. Пинги от анонимных администраторов и от имени каналов не
обрабатываются: у них нет идентификатора пользователя для личных списков и проверки прав.

При обновлении существующая кодовая фраза автоматически становится первым элементом
«Моих фраз». Все списки и участники сохраняются. Миграция выполняется один раз при запуске;
удалённые пользователем фразы при перезапуске не восстанавливаются.
Для обновления: `docker compose up -d --build bot` (не удаляйте volume).
Прежние команды управления заменены кнопками; `/start` возвращает в главное меню.

В списке максимум 200 username, повторы убираются. Сохраняются именно username:
если участник сменит имя, обновите список. Существование аккаунтов и членство в чате
при вводе не проверяются. Упоминания видны всем участникам чата, а управление списком — только владельцу.

## Администраторы и стикер-ответы

В `.env` перечислите личные Telegram ID администраторов бота через запятую:

```dotenv
ADMIN_IDS=123456789,987654321
```

Пробелы вокруг ID допустимы. Пустое значение означает отсутствие администраторов.
Это отдельные права: администратор группового чата не становится администратором бота.
После изменения `.env`: `docker compose up -d --force-recreate bot`, затем `/start` в личке.

У этих пользователей появляется кнопка **Стикер-ответы**:

1. «Добавить пользователя» → введите его `@username`.
2. Отправьте боту выбранный стикер (обычный, анимированный или видеостикер).
3. Введите шанс ответа в процентах: например `25`, `12,5` или `100%`.

Правило сохраняется только после всех трёх шагов. В меню пользователя можно посмотреть
стикер, заменить его, изменить вероятность или удалить правило с подтверждением.
`0%` отключает ответы, `100%` отвечает на каждое доступное боту сообщение.
Вероятность проверяется независимо для каждого сообщения: `25%` не означает строго
одно из каждых четырёх сообщений.

Все администраторы видят и редактируют общие правила. Можно настроить нескольких
пользователей; на одного пользователя действует одно правило во всех группах с ботом.
Повторный выбор пользователя открывает его существующее правило.
Пользователь сохраняется по Telegram ID: после смены username правило продолжает
работать, хотя меню показывает username, указанный при настройке.

Бот отправляет стикер ответом на исходное сообщение, включая фото, видео, голосовые
и стикеры без подписи. В личке, на служебные события, сообщения ботов и сообщения от
имени канала автоматических ответов нет. Бот должен видеть сообщения группы и иметь
право отправлять стикеры. Редактирование старого сообщения не запускает повторный ответ.
Сообщения альбома обрабатываются по отдельности.

Правила и сами стикеры сохраняются в SQLite и переживают перезапуск. Удаление ID из
`ADMIN_IDS` отзывает управление, но не удаляет уже настроенные правила. Для отключения
правила задайте 0% или удалите его через меню.
`PING_COOLDOWN_SECONDS` относится только к упоминаниям и не влияет на стикеры.
Лимиты Telegram (включая FloodWait) могут помешать отправке даже при 100%; ошибки
автоматических ответов записываются в лог, без дополнительных сообщений в группе.

Бот повторно отправляет исходный стикер Telegram, сохраняя его ID и набор, без
загрузки как обычной картинки или файла. Устаревшая ссылка обновляется из набора.
Если набор недоступен или стикер не принадлежит набору, может понадобиться отправить
его заново через «Изменить стикер». Уже сохранённые правила работают без пересоздания.

## `@all`

Отправьте `@all` отдельно или как отдельное слово в сообщении.
Бот сразу запрашивает доступный Telegram список участников с пагинацией, а не собирает
их по истории сообщений. Упоминает людей по ID, включая участников без username;
боты и удалённые аккаунты пропускаются. При наличии `@all` в сообщении он имеет приоритет над личным списком.

В `.env`:

```dotenv
ALL_ALLOW_EVERYONE=True
```

`True` — всем участникам; `False` — только администраторам и владельцу текущего чата.
После изменения примените настройки: `docker compose up -d --force-recreate bot`.

Telegram может ограничивать выдачу участников больших/скрытых групп даже через MTProto.
Если возвращено меньше записей, чем заявлено сервером, бот предупреждает и упоминает
доступных. Полный охват произвольного чата не гарантируется, как и доставка уведомлений:
она зависит от Telegram и настроек получателей.

Сообщения разбиваются на партии по 20 упоминаний с секундной паузой. В одном чате
одновременно выполняется один пинг; повторные вызовы во время отправки игнорируются.
`PING_COOLDOWN_SECONDS=30` задаёт паузу между пингами (0 отключает).
При FloodWait бот приостанавливает обработку на время, указанное Telegram; уже отправленные
партии не повторяются. Причина и длительность доступны в логах.

## Разработка и проверка

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
```

Для запуска вне Docker выполните `.venv/bin/python -m pingbot` и укажите в `.env`
доступный хост/порт уже запущенного Flowseal. По умолчанию Compose не публикует порт прокси.
Данные такого запуска находятся в `DATA_DIR=data`.

Проверка с настоящим Telegram после заполнения ключей: создание списка и нескольких фраз через кнопки в личке,
вызов фразы в тестовой группе, `@all` с участником без username, повторная проверка
обычным участником и администратором после `ALL_ALLOW_EVERYONE=False`, перезапуск
контейнера и проверка сохранности списков.

Источники: [Telethon: MTProto](https://docs.telethon.dev/en/stable/concepts/botapi-vs-mtproto.html),
[MTProto proxy](https://docs.telethon.dev/en/stable/basic/signing-in.html#using-mtproto-proxies),
[получение участников](https://core.telegram.org/method/channels.getParticipants),
[ограничения iter_participants](https://docs.telethon.dev/en/stable/modules/client.html#telethon.client.chats.ChatMethods.iter_participants),
[Flowseal](https://github.com/Flowseal/tg-ws-proxy).
