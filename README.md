# Pingbot

Telegram-бот на Python, Telethon и SQLite. Пользователи создают личные списки
упоминаний и кодовые фразы. Администраторы настраивают события через кнопки:
**одно условие → одно действие**.

## Запуск в Docker

Используются два контейнера в общей сети: `bot` и `tg-ws-proxy` от Flowseal.
Бот подключается через MTProto. Порт прокси наружу не публикуется; исходники
прокси закреплены на конкретном коммите в `compose.yaml`.

1. Создайте бота через [BotFather](https://t.me/BotFather), получите токен.
2. Получите `API_ID` и `API_HASH` в [API development tools](https://my.telegram.org).
   Они нужны Telethon даже для аккаунта бота; пользовательская авторизация в приложении не нужна.
3. Создайте `.env`:

   ```sh
   cp .env.example .env
   python3 -c 'import secrets; print(secrets.token_hex(16))'
   ```

4. Заполните `BOT_TOKEN`, `API_ID`, `API_HASH`, `TG_WS_PROXY_SECRET`.
   Для секрета прокси используйте сгенерированные 32 hex-символа **без** `dd`/`ee`.
   В `ADMIN_IDS` укажите личные Telegram ID администраторов через запятую.
5. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs -f bot
   ```

6. В личке с ботом нажмите «Старт». Добавьте бота в группу и назначьте администратором:
   ему необходимо видеть сообщения, получать участников и отправлять выбранные типы медиа.

Если бот не администратор, для чтения обычных сообщений отключите Privacy Mode
через `/setprivacy` в BotFather и добавьте бота в группу заново. Получение участников
и некоторых событий состава всё равно может потребовать административных прав.

## Настройки `.env`

| Поле | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен BotFather |
| `API_ID`, `API_HASH` | Данные приложения Telegram |
| `TG_WS_PROXY_SECRET` | Общий секрет бота и прокси |
| `TG_WS_PROXY_HOST`, `TG_WS_PROXY_PORT` | Адрес прокси; Compose задаёт хост `tg-ws-proxy` |
| `TG_WS_PROXY_DC_IPS` | Адреса DC для Flowseal, исходные значения есть в примере |
| `ADMIN_IDS` | Например `123456789,987654321`; пусто — администраторов бота нет |
| `ALL_ALLOW_EVERYONE` | `True`: команду `@all` могут вызывать все; `False`: только администраторы чата |
| `PING_COOLDOWN_SECONDS` | Пауза между обычными пингами в чате; по умолчанию 30 секунд |
| `DATA_DIR` | Данные локального запуска; в Compose фиксирован `/app/data` |

Администратор Telegram-группы и администратор бота — разные роли.
Изменение `.env` применяется пересозданием контейнера:

```sh
docker compose up -d --force-recreate bot
```

## Личные списки и фразы

Все операции выполняются кнопками в личке. `/start` открывает главное меню.
Текстом вводятся только значения, запрошенные ботом.

- **Мои списки**: добавить, посмотреть участников, заменить их, переименовать или удалить список.
- **Мои фразы**: добавить, изменить или удалить кодовую фразу.

Пример: создайте списки `дота 2` и `сотрудники`, затем фразы `я иду домой` и
`я иду на работу`. Любая фраза подходит к любому **вашему** списку:

```text
я иду домой дота 2
я иду на работу дота 2
я иду домой сотрудники
я иду на работу сотрудники
```

Сопоставляется всё сообщение без учёта регистра и лишних пробелов. Если подходят
несколько пар, выбирается наиболее длинная фраза с существующим списком.
Фраза `я иду домой` добавляется при регистрации; её можно удалить.
В списке до 200 username, повторы удаляются. Существование аккаунта и членство в
группе при вводе не проверяются; сменившийся username нужно обновить самостоятельно.
Списки и фразы изолированы по владельцу. Их содержимое при вызове видно всему чату.

## События: независимые пары

Администраторы из `ADMIN_IDS` видят кнопку **События** с тремя разделами:
**События**, **Условия**, **Действия**. Эти настройки общие для всех администраторов.

Каждое событие содержит ровно одно условие и одно действие. Объединений И/ИЛИ нет.
Чтобы использовать два условия и два действия во всех сочетаниях, создайте четыре
события: У1 → Д1, У1 → Д2, У2 → Д1, У2 → Д2. Одни и те же элементы выбираются повторно,
копировать их не требуется. Если сработали несколько пар, выполняется действие каждой
пары, даже если в них выбран один и тот же элемент действия.

### Пример: стикер на слово «злой»

1. «События» → «Условия» → «Добавить» → название → «Ключевые слова».
2. Введите `злой` или несколько слов через запятую/с новой строки.
3. Выберите «Любой пользователь / весь чат» либо укажите `@username`.
4. «Действия» → «Добавить» → название → «Стикер» → отправьте стикер.
5. В разделе «События» создайте событие, выберите это условие и действие.
6. При необходимости настройте чаты, шанс и паузу. Нажмите «Включить».

Новые события выключены, вероятность по умолчанию 100%, пауза — 60 секунд.
Вероятность проверяется независимо на каждом подходящем обновлении: 25% не означает
строго одно из четырёх сообщений. 0% полностью отключает срабатывания.
Пауза задаётся в секундах (0–86400) отдельно для каждой пары и каждого чата.
`PING_COOLDOWN_SECONDS` на события не влияет.

### Условия

| Тип | Настройка и поведение |
| --- | --- |
| Ключевые слова | 1–50 слов/фраз через запятую или новую строку, до 100 символов каждое. Достаточно любого слова из списка; совпадение по границам слова, без учёта регистра. «злой» не совпадает с «незлой» |
| Количество сообщений | Порог 1–10000 сообщений за последние 1–86400 секунд |
| Вход в беседу | Вступление или добавление участника |
| Выход из беседы | Выход или исключение участника |
| Сообщения пользователя | Любое новое сообщение указанного пользователя |
| Любое сообщение | Любое новое сообщение, включая медиа без текста |

Для условий можно выбрать конкретного пользователя по `@username`. Сохраняется его
Telegram ID, поэтому смена username не меняет адресата. Без конкретного пользователя
счётчик учитывает **весь чат**, а не отдельный счётчик каждого автора.

Счётчик использует скользящее окно: условие выполнено, если сообщений в нём **не меньше**
порога. Проверка происходит на каждом новом сообщении. После срабатывания счётчик не
обнуляется; повторные ответы ограничиваются паузой события. Например, при пороге
5 за 60 секунд и паузе 30 секунд первое действие выполняется на пятом сообщении,
а следующее — не раньше чем через 30 секунд и только если порог всё ещё выполнен.

Ключевые слова проверяются в тексте и подписях медиа. Редактирование сообщения не
считается новым событием. Сообщения ботов и сообщения от имени канала/анонимного
администратора не обрабатываются. У альбома каждое сообщение учитывается отдельно.
При входе/выходе выбранный пользователь — сам вступивший/вышедший участник, а не тот,
кто его добавил или исключил.

### Действия

| Тип | Что происходит |
| --- | --- |
| Ответ текстом | Ответ на исходное сообщение; если его нет у события входа/выхода — обычное сообщение |
| Сообщение в чат | Отдельное текстовое сообщение |
| Стикер | Исходный стикер Telegram, не картинка и не загруженный заново файл |
| Фото, видео, GIF, документ, голосовое, аудио | Повторная отправка выбранного администратором медиа |
| Реакция emoji | Реакция на исходное сообщение; emoji должен быть разрешён в группе |
| Упомянуть участника события | Упоминание автора сообщения или вступившего/вышедшего участника по ID |
| Упомянуть список @username | До 200 адресатов, заданных непосредственно в действии |
| Упомянуть всех | Запрос участников и упоминания по ID |
| Опрос | Вопрос и 2–10 вариантов, каждый с новой строки |
| Игровой emoji | 🎲, 🎯, 🏀, ⚽, 🎳 или 🎰 |

Текст действия — до 2000 символов, отправляется без разметки и без подстановок.
Для медиа отправьте боту сообщение нужного типа во время настройки действия.
Подпись исходного медиа отдельно не копируется. Не удаляйте исходное сообщение из
лички: оно используется для обновления истёкшей ссылки Telegram. Если оно удалено,
может потребоваться заново настроить медиа действия.

Действие реакции нельзя включить в паре со входом/выходом: у этих обновлений может
не быть сообщения. Такое сочетание меню отклоняет. Остальные действия могут
использоваться с любым из перечисленных условий. Действий удаления сообщений,
исключения и ограничения участников нет.

Автоматическое действие «Упомянуть всех» настраивается только администраторами бота
и не зависит от `ALL_ALLOW_EVERYONE`: эта переменная управляет пользовательской командой `@all`.

### Включение, изменения и чаты

- Событие, условие и действие имеют отдельные кнопки включения/выключения.
- Выключенное условие или действие останавливает все пары, использующие его.
- Настройка общего элемента меняет поведение всех использующих его событий.
- Выбор другого условия/действия выключает событие до явного повторного включения.
- Удаление элемента требует подтверждения и выключает зависимые события.
- Можно выбрать все группы либо конкретные чаты. Пустой список означает все группы.
  Меню чатов пополняется по полученным сообщениям; также можно ввести отрицательные
  Telegram ID групп через запятую.
- «Отмена» или переход в другой раздел отменяет незавершённый ввод.

## Старые стикер-ответы

Существующие правила автоматически становятся включёнными событиями с прежними
пользователями, стикерами и шансами. Для сохранения прежнего поведения у них пауза 0.
Отдельный старый механизм ответов параллельно не запускается.

Кнопка **Стикер-ответы** оставлена как совместимый способ настройки. Созданные через неё
правила также появляются в событиях. В карточке есть кнопка «Настроить событие».
Шанс синхронизируется между обоими меню. Для перенесённого действия стикер меняется
через старый раздел, либо можно создать новое действие и выбрать его в событии.

Исходный стикер сохраняет ID и набор. Если ссылка истекла, бот обновляет её через набор.
Если набора больше нет или стикер не принадлежит набору, отправьте его заново.
Удаление администратора из `.env` отзывает его доступ, но не удаляет общие правила.

## Команда `@all`

Напишите `@all` отдельно или как отдельное слово. Бот сразу запрашивает участников
с пагинацией и упоминает людей по ID, включая людей без username. Боты и удалённые
аккаунты пропускаются. Упоминания разбиваются на партии. Telegram может вернуть
неполный список; бот предупреждает об этом. Полный охват произвольной группы и
получение уведомлений всеми участниками не гарантируются.

`ALL_ALLOW_EVERYONE=False` ограничивает команду администраторами текущей группы.
В одном чате обычные пинги не ставятся в очередь, действует `PING_COOLDOWN_SECONDS`.
Если сообщение также подходит под событие, выполняются и событие, и обычный пинг.

## Данные, обновление и ограничения

Данные и сессия Telethon лежат в volume `bot-data`. Миграции SQLite выполняются при
запуске: списки, фразы и старые настройки сохраняются. Для обновления:

```sh
docker compose up -d --build bot
```

`docker compose down` сохраняет данные, `docker compose down -v` удаляет volume.
Перед обновлением работающего экземпляра сохраните резервную копию volume при
остановленном боте. Не запускайте несколько экземпляров с одной сессией.
`.env`, базы и сессии исключены из Git и Docker build context. Сам Flowseal может
писать секрет прокси в лог — удаляйте секрет перед публикацией логов.

Для счётчиков сохраняются только ID чата, сообщения, автора и время получения,
без содержания сообщений. Записи старше 24 часов удаляются при поступлении следующих
обновлений. Эти счётчики, защита от повторной обработки сообщений и паузы событий
переживают перезапуск. История до первого запуска не загружается. Пропущенные при
отключении обновления не воспроизводятся специально.

Для состава групп используются `ChatAction` и административные обновления участников.
Telegram не гарантирует доставку всех событий выхода, особенно в больших группах;
назначение бота администратором расширяет доступные обновления, но не гарантирует
полноту. Дубли одного изменения из двух источников подавляются в пределах 3 секунд;
два одинаковых изменения одного пользователя за эти 3 секунды могут считаться одним.

Ошибки действий пишутся в лог с ID события, действия и чата. Ошибка одной пары не
останавливает остальные. При FloodWait обработка приостанавливается на указанное
Telegram время; автоматических повторов уже начатых действий нет. Пауза события
отсчитывается от попытки выполнения, в том числе неудачной. Работа зависит от прав
бота, доступности медиа и лимитов Telegram, поэтому даже 100% не гарантирует отправку.

## Разработка и проверки

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m compileall -q pingbot tests
```

Локальный запуск: `.venv/bin/python -m pingbot`, с доступным MTProto-прокси и заполненным
`.env`. Compose по умолчанию не открывает порт прокси на хост.

Автоматические тесты проверяют меню, доступ администратора, миграции, независимые пары,
скользящие окна, вероятность, паузы, повторы обновлений, нативную отправку медиа и
совместимость существующих функций. Реальные Telegram-вызовы заменяются тестовыми
клиентами; Docker и отправку в Telegram нужно отдельно проверить на вашем сервере.

Приёмка в тестовой группе: четыре пары У1/У2 × Д1/Д2; выключение общего действия;
счётчик с пользователем и без; фильтр чатов; вступление и выход; статический и
анимированный стикер; реакция; опрос; перезапуск с сохранением настроек и счётчиков.

Источники: [Telethon / MTProto](https://docs.telethon.dev/en/stable/concepts/botapi-vs-mtproto.html),
[подключение к прокси](https://docs.telethon.dev/en/stable/basic/signing-in.html#using-mtproto-proxies),
[события состава групп](https://docs.telethon.dev/en/stable/modules/events.html#telethon.events.chataction.ChatAction),
[получение участников](https://core.telegram.org/method/channels.getParticipants),
[Flowseal](https://github.com/Flowseal/tg-ws-proxy).
