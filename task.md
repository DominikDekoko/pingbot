# Состояние проекта Pingbot

Обновлено: 14 октября 2026 года.

## Назначение и развёртывание

Telegram-бот для личных списков упоминаний и автоматических событий в группах.
Стек: Python, Telethon 1.45.0, SQLite. Два Docker-контейнера в общей сети:
бот и MTProto-прокси Flowseal tg-ws-proxy. Конфигурация и ключи — в отдельном `.env`;
перечень полей — `.env.example`. Данные и сессия сохраняются в Docker volume.

## Реализовано

### Личные функции

- Регистрация через «Старт» и управление кнопками «Мои фразы» / «Мои списки».
- Несколько кодовых фраз у каждого пользователя; каждая подходит к любому его списку.
- Создание, просмотр, изменение и удаление фраз и списков; переименование списков.
- Вызов: полная кодовая фраза + название списка, без учёта регистра и лишних пробелов.
- Изоляция владельцев; одинаковые названия у разных пользователей допустимы.
- `@all`: запрос доступных участников с пагинацией, упоминания по ID.
- Переключатель `ALL_ALLOW_EVERYONE=True/False` и пауза обычных пингов.

### Администраторы

- Список личных Telegram ID в `ADMIN_IDS`, через запятую.
- Проверка прав на кнопках и на каждом шаге ввода, включая незавершённые диалоги.
- Общие настройки автоматизации для всех администраторов бота.

### События — согласованная модель

**Ровно одно условие → ровно одно действие. Условия не объединяются через И/ИЛИ.**

Одни и те же условия и действия используются в разных событиях. Для сочетаний
У1/У2 и Д1/Д2 создаются четыре независимые пары: 11, 12, 21, 22.

- Отдельное включение/выключение события, условия и действия.
- Имена, редактирование параметров, удаление с подтверждением, страницы меню.
- Выбор чатов: все группы либо конкретные ID/группы из меню.
- Вероятность 0–100% и пауза 0–86400 секунд для каждой пары в каждом чате.
- Новое событие выключено; для включения требуется одна активная пара.
- Замена состава выключает событие до повторного включения.
- Удаление общего элемента выключает зависимые события.

Условия:

1. Ключевое слово или список слов/фраз: совпадение любого элемента по границам слов.
2. Не менее N сообщений за заданное время в секундах, скользящее окно.
   Если конкретный пользователь не выбран, считается весь чат; если выбран — только он.
3. Вступление/добавление в группу.
4. Выход/исключение из группы.
5. Любое сообщение конкретного пользователя.
6. Любое сообщение.

Для условий предусмотрен необязательный фильтр пользователя, кроме условия
«Сообщения пользователя», где адресат обязателен. Пользователь выбирается по username,
но хранится по Telegram ID.

Действия:

- Текстовый ответ на исходное сообщение и отдельное сообщение в чат.
- Стикер, фото, видео, GIF, документ, голосовое, аудио.
- Emoji-реакция на сообщение.
- Упоминание участника события, заданного списка username или всех доступных участников.
- Опрос и игровые emoji.

Модерация (удаление сообщений, ограничения и исключение участников) не входит
в согласованный объём. Реакция на вход/выход отклоняется в настройках, поскольку
у такого обновления может не быть сообщения. Текстовый ответ в таком случае
отправляется отдельным сообщением.

### Совместимость и хранение

- Старые стикер-ответы мигрируют в события с прежней вероятностью и паузой 0.
- Старый раздел «Стикер-ответы» сохранён; новые правила из него также создают события.
- Отправляется исходный Telegram-стикер, без преобразования в скачиваемую картинку.
- Схема SQLite версии 3: повторно используемые элементы, пары, связи, известные чаты,
  история временных меток сообщений и время попыток выполнения.
- Счётчики, паузы, настройки и черновики сохраняются после перезапуска.
- Повторная обработка одного сообщения подавляется; дубли изменений состава
  от ChatAction и административного обновления подавляются в пределах 3 секунд.
- Текст групповых сообщений для счётчиков не сохраняется. Метаданные старше 24 часов
  очищаются при следующих обновлениях.
- Ошибки действий изолированы; FloodWait останавливает обработку на срок Telegram.

## Основные модули

| Файл | Ответственность |
| --- | --- |
| `pingbot/bot.py` | Маршрутизация сообщений, личные пинги и `@all` |
| `pingbot/menus.py` | Личные меню |
| `pingbot/automation.py` | Проверка условий, выполнение действий, обновления состава |
| `pingbot/event_menus.py` | Кнопки и пошаговая настройка событий |
| `pingbot/event_store.py` | Схема автоматизации, связи, счётчики и миграция старых правил |
| `pingbot/storage.py` | Общая SQLite-база, личные данные и совместимость стикер-ответов |
| `pingbot/stickers.py` | Прежнее меню стикеров и отправка исходного Telegram-документа |
| `pingbot/config.py` | Загрузка и проверка `.env` |
| `pingbot/__main__.py` | Подключение, обработчики, завершение работы |

## Проверка и оставшиеся ограничения

Автоматические тесты покрывают прежние функции и новую модель событий, включая
четыре независимые пары, права, миграции, время, вероятность, паузы и меню.
Список тестов и команды запуска находятся в README и каталоге `tests`.

Для завершения эксплуатационной приёмки требуется проверка с реальным Telegram:
подключение через прокси, права в группе, полный набор медиа, реакция, опрос,
вход/выход и перезапуск контейнера. Автотесты не заменяют эту проверку.

Telegram может ограничить список участников и доставку событий выхода из больших
групп. Полнота `@all`, уведомлений и событий состава не гарантируется. Недоступное
исходное медиа или удалённый стикерпак могут потребовать повторного выбора медиа.
Бот рассчитан на один экземпляр с общей SQLite-базой и сессией.
